ALTERACAO LIMITADA
LCD e SD compartilham SPI no SKU29667 (MOSI38, SCLK39, MISO40; CS41/45).
A base inicializava/desenhava no LCD antes de colocar o SD em modo SPI.
A recomendacao oficial exige inicializar o SD primeiro, mantendo os outros CS
altos. Agora primeSharedSd tenta um mount sem formatacao, fecha-o, e so depois
inicia o LCD. Sem cartao ou com mount falho a tela continua inicializando; a
leitura normal tenta novamente e registra o erro. O cartao permanece em modo
SPI apos unmount ate perder alimentacao. Nenhum clock foi alterado.
Isso corrige uma divergencia verificavel de inicializacao; a relacao causal com
as duas placas so pode ser confirmada fisicamente, inclusive apos partida fria.
Fonte: https://docs.espressif.com/projects/esp-idf/en/v5.0.2/esp32s3/api-reference/peripherals/sdspi_share.html

Os acessos OTA ao SD e as transferencias do LCD ja usam a mesma trava SPI.
Nao se encontrou transferencia LCD assincrona solta nem evidencia de defeito
especifico no core 3.3.12 confirmado pelo usuario. Nao se alterou retomada HTTP,
206/Content-Range, reinicio 200, timeout, tamanho exigido ou politica de limpeza.

DIAGNOSTICO RAM
A tela Atualizacao mostra o ultimo problema de boot das artes ou de conferencia
OTA: fase, arquivo, motivo, offset, esperado/obtido e codigo da API quando existe.
Distingue abrir, tamanho, leitura curta, assinatura PKA1, comprimento, CRC do
cabecalho, catalogo, CRC dos dados, SHA e erro da API SHA. O SHA exibido e somente
um prefixo de 32 bits para diagnostico; a aceitacao compara todos os 256 bits.
Codigo zero significa que a API nao forneceu detalhe, nao que a midia esta boa.
Ao iniciar, o boot usa tamanho/cabecalho/CRC como antes; o OTA exige tambem SHA.
Retornar e testar a conexao preservam o registro. Desligar perde o registro.
Nao ha log escrito no cartao que falhou, credenciais, bytes de saves ou novo NVS.
As APIs flush/close do core nao retornam confirmacao duravel; o candidato nao
atribui uma falha especificamente a flush, a FAT ou ao hardware sem evidencia.

SEGURANCA
Falha de validacao continua impedindo ativacao/reinicio de sucesso. Partes seguem
a mesma tentativa de remocao; uma falha de SD pode impedir a propria remocao.
A instalacao de artes continua usando nome CRC, sem sobrescrever o arquivo
generico ativo. O boot so limpa outros pacotes/generico depois de validar um
arquivo com nome CRC. Isso nao oferece retencao completa para rollback antigo.

ou reset de slots foi adicionada. Falta de PSRAM continua seguindo o tratamento
existente, nao foi convertida em reparo automatico.
